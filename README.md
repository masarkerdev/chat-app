# Dujone — শুধু দুইজনের প্রাইভেট চ্যাট

Messenger বা WhatsApp-এর মতো একটি রিয়েল-টাইম চ্যাট ওয়েব অ্যাপ, যেখানে **ঠিক দুইজন** মানুষ চ্যাট করতে পারবেন। তৃতীয় কেউ অ্যাকাউন্ট খুলতে চাইলে ডাটাবেস নিজেই সেটা আটকে দেবে।

**টেক স্ট্যাক:** Next.js 16 (App Router) + TypeScript + Supabase (Auth, Postgres, Realtime, Storage) + Web Push। হোস্টিং হবে Vercel-এ। দুটোরই ফ্রি প্ল্যান যথেষ্ট।

## ফিচার

- রিয়েল-টাইম মেসেজ, পেইজ রিফ্রেশ ছাড়াই
- ✓ পাঠানো হয়েছে, নীল ✓✓ দেখা হয়েছে (seen)
- অনলাইন স্ট্যাটাস, "টাইপ করছে…" এবং "সর্বশেষ দেখা" সময়
- ছবি পাঠানো। ছবি নিজে থেকেই ছোট হয়ে আপলোড হয় এবং প্রাইভেট স্টোরেজে থাকে
- নিজের মেসেজ দুজনের কাছ থেকেই মুছে ফেলা যায় (লং-প্রেস, অথবা ডেস্কটপে রাইট-ক্লিক)
- নেটওয়ার্ক ব্যর্থ হলে "আবার পাঠান" বোতাম
- উপরে স্ক্রল করলে পুরোনো মেসেজ লোড হয় (প্রতিবার ৫০টি)
- **Web Push নোটিফিকেশন। অ্যাপ বা ব্রাউজার বন্ধ থাকলেও ফোনে নোটিফিকেশন আসে**
  - পরপর কয়েকটি মেসেজ এলে একটিই নোটিফিকেশনে জমা হয় ("নুসরাত · ৩টি নতুন মেসেজ")
  - চ্যাট স্ক্রিনে খোলা থাকলে নোটিফিকেশন আসে না, আর চ্যাট খুললে পুরোনো নোটিফিকেশন সরে যায়
  - একজনের একাধিক ডিভাইস (ফোন + ল্যাপটপ) থাকলে সব ডিভাইসেই নোটিফিকেশন যায়
- **ইমোজি রিঅ্যাকশন**: মেসেজে লং-প্রেস (ডেস্কটপে রাইট-ক্লিক) করে ❤️ 😂 😮 😢 🙏 👍; ডাবল-ট্যাপ করলে সরাসরি ❤️। একই ইমোজি আবার দিলে সরে যায়
- **নির্দিষ্ট মেসেজে রিপ্লাই**: মোবাইলে মেসেজটা ডান দিকে টানুন, অথবা মেনু থেকে "রিপ্লাই"। উদ্ধৃতিতে চাপলে মূল মেসেজে চলে যায়
- **থিম ও রঙ**: ৬টি রঙের জোড়া, নিজের পছন্দের রঙ, লাইট/ডার্ক/ফোনের মতো। পছন্দটা প্রতিটি ডিভাইসে আলাদা থাকে
- মেনু (⋮) থেকে নাম ও **পাসওয়ার্ড পরিবর্তন** (বর্তমান পাসওয়ার্ড দিয়ে যাচাই করে, দুর্বল পাসওয়ার্ড নেয় না)
- ফোনে অ্যাপের মতো ইনস্টল করা যায় (PWA)
- লাইট ও ডার্ক মোড, পুরো ইন্টারফেস বাংলায়

## সেটআপ (প্রায় ২০ মিনিট)

### ধাপ ১ — Supabase প্রজেক্ট তৈরি

1. [supabase.com](https://supabase.com)-এ নতুন প্রজেক্ট খুলুন। অঞ্চল হিসেবে **Singapore** বেছে নিন, এটা বাংলাদেশ থেকে সবচেয়ে কাছে।
2. বাম মেনু থেকে **SQL Editor → New query**-তে যান, `supabase/schema.sql` ফাইলের পুরো লেখা পেস্ট করে **Run** চাপুন।
   - এতে টেবিল, সিকিউরিটি রুল (RLS), দুইজনের সীমা, ছবির বাকেট, রিয়েলটাইম আর push সব একবারে তৈরি হয়ে যাবে।

> **আগের ভার্সন থেকে আপডেট করছেন?** নতুন `schema.sql` পুরোটা আবার Run করলেই হবে। ফাইলটি বারবার চালানো নিরাপদ, পুরোনো মেসেজ বা ইউজার মুছবে না।

### ধাপ ২ — নতুন সাইন-আপ বন্ধ করুন

**Authentication → Sign In / Providers**-এ গিয়ে **"Allow new users to sign up"** বন্ধ করে দিন।

### ধাপ ৩ — দুইজন ইউজার তৈরি

**Authentication → Users → Add user → Create new user**-এ গিয়ে দুজনের ইমেইল ও পাসওয়ার্ড দিন, **"Auto Confirm User"** টিক দিন।
তৃতীয় অ্যাকাউন্ট খোলার চেষ্টা করলে ত্রুটি দেখাবে, এটাই স্বাভাবিক আচরণ।

### ধাপ ৪ — VAPID key তৈরি (Web Push-এর জন্য, একবারই)

```bash
npm install
npm run vapid
```

দুটি key দেখাবে, **Public Key** আর **Private Key**। এগুলো পরের ধাপে লাগবে।

> ⚠️ key একবার তৈরি করে **আর বদলাবেন না**। বদলালে দুজনকেই আবার নোটিফিকেশন চালু করতে হবে।
> Private Key গোপন রাখবেন, GitHub-এ দেবেন না।

### ধাপ ৫ — লোকালি চালানো

```bash
cp .env.example .env.local
```

`.env.local` ফাইলে মানগুলো বসান:

```
NEXT_PUBLIC_SUPABASE_URL=https://xxxx.supabase.co
NEXT_PUBLIC_SUPABASE_ANON_KEY=eyJ...            # অথবা sb_publishable_...
NEXT_PUBLIC_VAPID_PUBLIC_KEY=BPx...             # ধাপ ৪-এর Public Key
VAPID_PRIVATE_KEY=abc...                        # ধাপ ৪-এর Private Key
VAPID_SUBJECT=mailto:আপনার-ইমেইল@gmail.com
NOTIFY_PREVIEW=true                             # false দিলে লক স্ক্রিনে মেসেজের লেখা লুকানো থাকবে
```

```bash
npm run dev
```

এরপর ব্রাউজারে `http://localhost:3000` খুলুন। পরীক্ষা করতে একটি সাধারণ উইন্ডো আর একটি Incognito উইন্ডোতে দুই অ্যাকাউন্ট দিয়ে লগইন করুন।

> Push নোটিফিকেশন `localhost`-এও কাজ করে। তবে আসল ফোনে পরীক্ষা করতে HTTPS লাগবে, তাই সেটা Vercel-এ ডিপ্লয়ের পর করবেন।

### ধাপ ৬ — Vercel-এ ডিপ্লয়

1. প্রজেক্টটি GitHub-এ পুশ করুন। `.env.local` ফাইলটি `.gitignore`-এ আছে, তাই পুশ হবে না।
2. [vercel.com](https://vercel.com) → **Add New → Project** → রিপো ইমপোর্ট করুন।
3. **Environment Variables**-এ উপরের **সবগুলো** মান যোগ করে **Deploy** চাপুন।
4. Supabase-এর **Authentication → URL Configuration**-এ গিয়ে **Site URL** হিসেবে আপনার Vercel লিংক বসান।

### ধাপ ৭ — ফোনে ইনস্টল ও নোটিফিকেশন চালু

- **Android (Chrome):** সাইট খুলে ⋮ মেনু থেকে **"Install app"** / **"Add to Home screen"** চাপুন। তারপর অ্যাপ খুলে উপরের ব্যানারে **"চালু করুন"** চাপুন।
- **iPhone (Safari, iOS 16.4 বা নতুন):** শেয়ার বাটন চেপে **"Add to Home Screen"** বেছে নিন, তারপর **হোম স্ক্রিনের আইকন থেকে** অ্যাপ খুলে **"চালু করুন"** চাপুন।
  iPhone-এ Safari-র সাধারণ ট্যাবে push কাজ করে না, এটা Apple-এর নিয়ম।
- **ডেস্কটপ (Chrome/Edge/Firefox):** মেনু ⋮ থেকে **"নোটিফিকেশন চালু করুন"** চাপুন।

দুজনকেই নিজের নিজের ডিভাইসে নোটিফিকেশন চালু করতে হবে।

## Web Push কীভাবে কাজ করে

```
প্রেরকের ফোন ──(১) মেসেজ সেভ──▶ Supabase
      │
      └──(২) POST /api/notify {messageId} + নিজের লগইন টোকেন ──▶ Vercel
                                                              │
               (৩) claim_push(): প্রেরক কিনা, আগে পাঠানো হয়েছে কিনা যাচাই
                   করে অপর পক্ষের ডিভাইস তালিকা দেয়
                                                              │
               (৪) VAPID দিয়ে সই করা, এনক্রিপ্টেড push ──▶ Google/Apple/Mozilla push সার্ভিস
                                                              │
প্রাপকের ফোন ◀──(৫) service worker নোটিফিকেশন দেখায় ◀───────────┘
```

- কোনো `service_role` key লাগে না। সার্ভার প্রেরকের নিজের টোকেন দিয়েই ডাটাবেসের ফাংশন ডাকে।
- একই মেসেজে দুবার ডাকলেও push একবারই যায় (`push_log` টেবিল)।
- কেউ অ্যাপ মুছে ফেললে বা অনুমতি বাতিল করলে (410 Gone) সেই ডিভাইস তালিকা থেকে নিজেই মুছে যায়।
- লগআউট করলে বা মেনু থেকে "নোটিফিকেশন বন্ধ করুন" চাপলে সেই ডিভাইসে আর push আসে না।

## নিরাপত্তা কীভাবে কাজ করে

| কী | কীভাবে নিশ্চিত করা হয়েছে |
|---|---|
| শুধু দুইজন | `auth.users`-এ ট্রিগার আছে। তৃতীয় ইউজার তৈরির চেষ্টা করলেই সেটা বাতিল হয় |
| অন্য কেউ মেসেজ পড়তে পারবে না | RLS চালু। শুধু সদস্যরাই পড়তে পারে, anon key দিয়ে কিছুই দেখা যায় না |
| অন্যের নামে মেসেজ পাঠানো যাবে না | ইনসার্টের সময় `sender_id = auth.uid()` বাধ্যতামূলক |
| অন্যের মেসেজ বদলানো বা মোছা যাবে না | UPDATE-এর কোনো পলিসি নেই, DELETE শুধু নিজের মেসেজে |
| ছবি | বাকেট প্রাইভেট। প্রত্যেকে নিজের ফোল্ডারে আপলোড করে, আর দেখা যায় ১ ঘণ্টা মেয়াদি signed লিংক দিয়ে |
| অনলাইন বা টাইপিং সিগন্যাল | প্রাইভেট রিয়েলটাইম চ্যানেল, শুধু সদস্যদের জন্য |
| Push সাবস্ক্রিপশন | টেবিল সরাসরি পড়া বা লেখা যায় না, শুধু নির্দিষ্ট ফাংশন দিয়ে। শুধু প্রেরক তার নিজের নতুন (১০ মিনিটের মধ্যের) মেসেজের জন্য push ট্রিগার করতে পারে |
| Push-এর বিষয়বস্তু | এন্ড-টু-এন্ড এনক্রিপ্টেড (aes128gcm)। Google বা Apple-এর push সার্ভার মেসেজ পড়তে পারে না |

`anon` key আর `NEXT_PUBLIC_VAPID_PUBLIC_KEY` ব্রাউজারে দেখা গেলেও সমস্যা নেই।
কিন্তু **`VAPID_PRIVATE_KEY` এবং Supabase `service_role` key কখনো `NEXT_PUBLIC_` নামে রাখবেন না।**

## সমস্যা সমাধান (নোটিফিকেশন)

| সমস্যা | সমাধান |
|---|---|
| "চালু করুন" বোতাম দেখা যায় না | Vercel-এ `NEXT_PUBLIC_VAPID_PUBLIC_KEY` সেট করে আবার Deploy করুন |
| iPhone-এ কাজ করে না | Safari ট্যাব নয়, হোম স্ক্রিনের আইকন থেকে খুলুন। iOS 16.4 বা নতুন লাগবে |
| "ব্লক করা আছে" বলছে | ব্রাউজারের সাইট সেটিংস (🔒 আইকন) থেকে Notifications → Allow করুন |
| Android-এ দেরিতে আসে | ফোনের Settings → Apps → Chrome → Battery-তে গিয়ে "Unrestricted" দিন (কিছু Xiaomi/Oppo/Vivo ফোনে লাগে) |
| কিছুই আসে না | Vercel → Project → Logs-এ `/api/notify`-এর এরর দেখুন। সাধারণত `VAPID_PRIVATE_KEY` ভুল থাকলে এমন হয় |

src/components/              হেডার, নোটিফিকেশন ব্যানার, মেসেজ তালিকা, বাবল, কম্পোজার, ছবি ভিউয়ার

## সীমাবদ্ধতা ও পরবর্তী ধাপ

- ভয়েস মেসেজ বা মেসেজ এডিট এখনো নেই। রিঅ্যাকশনের জন্য আলাদা push নোটিফিকেশন যায় না (অ্যাপ খোলা থাকলে সাথে সাথে দেখা যায়)।
- push পাঠানো হয় প্রেরকের ফোন থেকে `/api/notify` ডেকে। মেসেজ সেভ হওয়ার ঠিক মুহূর্তে ইন্টারনেট চলে গেলে কোনো একটি নোটিফিকেশন নাও যেতে পারে, তবে মেসেজ ঠিকই পৌঁছাবে। ১০০% নিশ্চিত করতে চাইলে পরে Supabase Database Webhook দিয়ে ট্রিগার করা যায়।
- Supabase ফ্রি প্রজেক্ট ৭ দিন একেবারে অব্যবহৃত থাকলে pause হয়ে যায়। নিয়মিত চ্যাট করলে এই সমস্যা হবে না।
